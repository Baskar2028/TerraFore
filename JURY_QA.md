# Jury Q&A (honest short answers)
**Problem?** Land acquisition delays (compensation, possession, disputes, clearances) are usually noticed after they happen, which raises cost and time.
**Solution?** TerraFore scores each project's delay risk, explains the drivers, recommends actions and lets officials simulate fixes: Predict → Explain → Recommend → Monitor.
**Users?** Land acquisition officers, project authorities and administrators, with role-based access.
**Only for government?** It is designed around public infrastructure acquisition, but the approach could serve any large project developer.
**Why use it?** It gives an early, explainable, ranked view of where attention is needed instead of a static status report.
**What is different?** Explanations in plain language, a what-if simulator, a lifecycle bottleneck view and compliance flags in one workflow.
**Data used / from where?** A synthetic dataset of 5,000 projects plus synthetic metadata (names, districts, coordinates, dates, forest flags) generated by scripts in this repo.
**Real or synthetic?** Synthetic. It is not real or government data, and the UI says so.
**How trained?** A scikit-learn pipeline (preprocessing + Logistic Regression) fitted on 80% of the synthetic data.
**How validated?** On a stratified 20% held-out set (ROC-AUC 0.94) and 5-fold CV. This shows technical feasibility only, not real-world accuracy.
**How to trust predictions?** Treat them as decision support: each score comes with drivers you can check. Real use needs validation on authorised historical data.
**What if wrong?** Officials keep final judgement; the disclaimer says estimates support, not replace, official judgement. Outcome recording and retraining are the correction loop.
**SHAP?** A method that attributes each prediction to input factors; for a linear model it is exact per feature relative to the dataset average.
**GIS / OpenStreetMap?** Leaflet draws project markers on free OpenStreetMap tiles. Coordinates here are synthetic (district HQ plus random offset).
**How do recommendations work?** Priority actions map risk-raising SHAP factors to standard actions. "Highest-impact fix" re-scores the project with the real model after a standard improvement per lever.
**Can students build this?** Yes: it uses open-source tools (FastAPI, scikit-learn, React) and no paid services.
**Scale across India?** The API is stateless apart from the database; PostgreSQL via `DATABASE_URL` and batch scoring (`/predict/batch`) support larger portfolios. Not load-tested.
**Integrate government systems?** Not built. `/api/v1/*` and `/predict/batch` are the integration surface; real integration would need agreements and security review.
**Protect sensitive data?** JWT auth, role checks, PBKDF2 password hashing, an audit log and optional state-level jurisdiction. Prototype-grade; production needs a security review.
**Forest land?** Forest clearance is a rule-based compliance flag, not a model feature. TerraFore does not decide whether forest land may be acquired and never recommends bypassing statutory clearance; it says to ensure clearance before proceeding with possession.
**Limitations?** Synthetic data, linear model, derived stage indicators, rule-based alerts, tested on Python 3.12 only.
**Future scope?** Real data validation, calibrated non-linear models, richer GIS layers, scheduled outcome ingestion, production security.
**Why this problem?** Acquisition delays are a common, costly bottleneck for public infrastructure, and early explainable signals are missing.
